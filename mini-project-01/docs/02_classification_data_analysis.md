## 1. 데이터 탐색 및 클래스 분포 (CP-01)

- **데이터 크기:** 12,330행, 18열
- **결측값 및 중복 행:** 125 (중복 행을 삭제하지 않은 이유: 수치적 우연일 가능성이 큼.
특히 중복이 발생된 데이터의 경우 방문 횟수, 머문시간 등 이 0인 경우가 다수 확인되어, 인터넷 쇼핑몰의 특성상 발생할 수 있는 데이터 이기 때문)
- **수치형 특성 분포의 특징(`ProductRelated`, `PageValues` 등):** 미구매자가 많은 데이터 특성 상 수치형 특성의 값이 0인 경우가 다수 발생,
방문횟수, 페이지 머문 기간 등 에서 일반적인 분포를 벗어난 값들이 포착됨, 페이지 가치의 경우 클 수록 구매로 이어질 확률이 높아보임.
- **구매(`Revenue=1`) 건수와 비율:** 1,908건 / 15.47%
- **미구매(`Revenue=0`) 건수와 비율:** 10,422건 / 84.53%

**분석:** 모두 미구매로 예측했을 때 Accuracy가 약 84.53%인 이유와 이 수치만으로 평가하기 어려운 점을 작성합니다.  
타겟이되는 구매·미구매의 데이터 불균형이 큰 데이터셋으로 모두 미구매라고 예측해도, 미구매자 비율만큼의 정확도가 발생함.
때문에 모델의 신뢰도가 저하되고, 본 프로젝트의 실제로 누가 물건을 구매할 것인가를 찾는 것을 목표로 하는데, 실제 구매자는 한 명도 맞추지 못함.

## 2. 계층화 데이터 분할 (CP-02)

- **Train:** 8,630건 / 구매 비율 15.48%
- **Validation:** 1,850건 / 구매 비율 15.48%
- **Test:** 1,850건 / 구매 비율 15.48%
- **`stratify`를 적용한 이유:** Target인 "Revenue"의 데이터 불균형 문제로 인해 학습, 검증, 평가에 데이터셋 내 비율과 동일하게 분할 되게 하기 위함.
- **1일차 회귀의 날짜 순서 분할과 다른 이유:** 1일차의 경우 시간의 흐름이 반영되어야 하는 시계열 데이터에 대한 회귀이고,
2일차의 경우 데이터의 순서와 상관 없이 Target을 분류이기 때문.

**분석:** Train·Validation·Test의 구매 비율이 유사한지 확인하고 의미를 1~2문장으로 작성합니다.
학습, 검증, 평가 간 구매 비율은 15.48%로 동일하며, 이는 데이터 불균형이 존재하는 데이터셋 에서 치우침 없이 모델을 안정적으로 학습시키고, 검증 및 평가 단계에서 일반화 성능의 향상을 위한 조치임.
